# v1 기능 정리

- 버전: v1 (백엔드 PR #7~#27, 프론트 PR #1~#23 까지 포함). 태그 `v1.0`은 실험 문서 정리 뒤 붙인다.
- 최종 갱신: 2026-10-05
- 관련 설계: ERD `('26.10.04) v1..md`, 실시간 `('26.10.05) live and results design.md`, 실험 `docs/experiments/v1-*.md`
- 저장소 사본: `docs/design/v1-features.md`

## 백엔드

### 인증 (v1 후반 추가)
- 이메일·비밀번호 가입과 로그인. JWT(HS256, jjwt 0.12.6), 만료는 120분 (`app.jwt.expiry-minutes`).
- `Authorization: Bearer` 헤더로 사용자를 식별한다. 예전 `X-User-Id` 헤더는 쓰지 않는다.
- `@LoginUser` 인자 리졸버가 토큰을 읽는다. 비밀번호는 BCrypt.
- API: `POST /api/auth/signup`, `POST /api/auth/login`, `GET /api/auth/me`.
- OIDC 소셜 로그인은 v1 밖. 제공자 설정이 필요해서 보류.

### 관리자 등록 (로드맵 2단계)
- 구역 등록, 좌석 격자 일괄 등록, 경기 등록 시 `GameSeat` 자동 생성.
- 대량 insert는 `JdbcTemplate` batch. IDENTITY 전략에서는 `saveAll`이 배치되지 않는다.
- 측정: `docs/experiments/v1-02-admin-bulk-insert.md`.

### 조회 (3단계)
- 경기 목록(페이징, 최대 100), 상세, 구역별 잔여석, 좌석맵.
- N+1은 DTO 직접 조회와 fetch join으로 없앴다. 측정: `docs/experiments/v1-03-seat-map-n-plus-1.md`.

### 예매·결제·취소 (4단계)
- 예매: 경기가 OPEN일 때만. 한 사용자가 한 경기에 최대 4매 (`TICKET_LIMIT_EXCEEDED`). 선택 좌석이 그 경기 소속인지 검증 (`RESERVATION-004`).
- 결제: Mock. `success` 값으로 성공·실패를 고른다. PG 연동 없음. 결제는 본인 예약만 가능(`FORBIDDEN`).
- 취소:
  - 결제 대기 예약: 선점한 좌석만 푼다.
  - 확정 예약: 경기 시작 전까지 전액 환불(`PAID → REFUNDED`), 좌석은 `AVAILABLE`로. 시작 후에는 거부 (`RESERVATION-007`).
  - 본인 예약만 취소 가능.
  - 결정 근거: ERD DR-09.
- 내 예약 목록: `GET /api/me/reservations` (로그인 사용자 기준). 프론트 마이페이지와 홈이 쓴다.

### 경기 진행과 실시간 (v1 후반 추가)
- 진행 이벤트: `GAME_STARTED`, `INNING_CHANGED`, `SCORE_CHANGED`, `SCORE_CORRECTED`, `PLAY`, `GAME_FINISHED`, `GAME_CANCELLED`. 관리자 API로 기록한다.
- 경기 안 이벤트 번호(`seq`)는 경기 행을 잠가서 매긴다. SSE 재접속은 `Last-Event-ID`로 빠진 이벤트를 다시 보낸다.
- 시작 시각 전에는 중계를 시작할 수 없다 (`GAME-010`). 도메인 `Game.start(now)`에서 막는다.
- 실시간 채널: 경기 중계(`GameLiveEventHub`), 채팅(`GameChatHub`), 좌석 상태(`SeatStatusHub`). 모두 커밋 뒤에 보낸다(`afterCommit`).
- 좌석 "고르는 중" 표시: 사용자가 고르는 좌석을 30초 TTL로 다른 사용자에게 보인다. 예매가 아니다(`SeatSelectionService`). 이중 예매 방지는 v2 범위.

### 일정 배치 (v1 후반 추가, PR #25)
- 매일 자정(Asia/Seoul)에 10개 구단을 무작위로 섞어 5경기를 만든다. 시작 18:30, 경기 시간 2~7시간(30분 단위).
- 예매는 경기 하루 전부터 열린다. 같은 날짜 경기가 있으면 다시 만들지 않는다(멱등).
- 서버 기동 시 보충: 오늘 첫 경기 전이면 오늘, 지났으면 내일 경기를 만든다.
- 예정 종료 시각(`plannedEndAt`)이 있는 배치 경기만 중계 생성기가 돌린다.

### 중계 생성기 (데모)
- `app.live-simulator.enabled`로 켜는 데모용. 시작 시각이 된 배치 경기를 시작하고 득점·플레이·이닝을 실제 페이스(득점 5~8분, 이닝 10분 안팎)로 쌓는다.
- 관리자 API와 같은 경로로 들어가므로 DB 기록과 SSE가 실제 입력과 같다.
- 종료: 예정 종료 시각이 지나면 끝낸다. 정규 9이닝 뒤 동점이면 12회에서 강제 종료한다.
- 선수는 가상 이름이다(구단별 14명). 실제 선수 기록을 쓰지 않는다.

### 팀 순위 (v1 후반 추가, PR #26)
- `GET /api/standings`: 종료된 경기로 10개 구단 순위를 계산한다. 새 테이블 없이 조회 시 계산.
- 승률은 무승부를 뺀 승/(승+패). 게임차는 ((1위 승 - 내 승) + (내 패 - 1위 패)) / 2.
- 정렬: 승률, 승수, 패수, 팀 이름. 경기가 없는 팀도 0-0으로 포함.

### 시드 (5단계)
- `seed` 프로필: 구역 30, 좌석 22,536, 경기 5 (예매 오픈 2). 구단 이름은 실제 KBO 10개 구단, 일정은 임의 값.
- 측정: `docs/experiments/v1-05-seeding.md`.

### 정리 (이슈 #3·#5·#6)
- 상태 컬럼: `varchar(20)`. 상태 값 추가에 `ALTER TABLE`이 필요 없다 (ERD DR-10).
- 시각: `TimeConfig`의 Asia/Seoul `Clock`으로 `createdAt`과 취소·시작 판정을 통일 (ERD DR-11).
- 에러 코드: `SEAT-008`, `RESERVATION-007`, `PAYMENT-002`, `GAME-010`, `AUTH-001~004`, `PLAYER-001` 등 추가.

### 리팩터링 (PR #27)
- 중계 생성기를 역할별로 나눴다: `LiveGameSimulator`, `EventRoll`, `RosterPicker`, `InningRules`.
- 대입만 하는 생성자 32개를 `@RequiredArgsConstructor`로 바꿨다. 동작은 같다.
- 코드 규칙은 `docs/conventions/code-style.md` 참고.

## 프론트엔드

| 화면 | 기능 |
|---|---|
| 홈 | 다음 경기 히어로(D-day), 지금 진행 중, 내 예매, 오늘의 경기, 팀 순위 위젯, 다가오는 경기, 이벤트 배너. 위젯 순서·크기는 편집기로 바꾸고 이 브라우저에 저장 |
| 예매 목록 | 경기 카드 그리드, 상태 필터. 카드는 진행 상태에 맞는 화면으로 이동(예정 → 예매, 진행 중 → 중계, 종료 → 기록) |
| 예매 화면 | 돔 모양 좌석 지도(canvas, 확대·축소·이동), 구역 목록에서 줌인, 구역 포커스 음영, 선택 좌석 하단 바, 다른 사용자가 고르는 좌석 표시, 예매·결제·취소 |
| 로그인 | 가입·로그인 (`/login`). 예매는 로그인 필요 |
| 중계 | 진행 상황 스코어보드, 이벤트 타임라인(최신순), 채팅(로그인 필요) |
| 기록 | 경기 기록 화면(플레이 종류 필터, 선수별 집계), 종료 경기 목록 |
| 팀별 일정 | 팀 선택, 팀 경기 목록(홈/원정, 예매 상태) |
| 순위 | `/standings` 전체 순위표 (승·무·패, 승률, 게임차), 30초마다 갱신 |
| 마이페이지 | 계정 요약, 상태 필터, 예매 카드, 예매 완료·결제 대기 건 취소 (서버 기준 목록) |
| 공통 | 시스템·라이트·다크 테마, 서버 시각을 한국 시각으로 표시 |

### 이 브라우저에만 저장되는 것
- 홈 위젯 배치 (`ballpark-booking.home-layout-v2`).
- 테마 (`ballpark-booking.theme`).
- 로그인 토큰 (`ballpark-booking.token`). 서버에 세션은 없다.

### 제외된 것 (v1 범위 밖)
- 관리자 화면: 프론트에서 제거. 관리는 API로만.
- 소셜 로그인(OIDC), 토큰 갱신: 제공자 설정이 필요해서 보류.
- 좌석 이중 예매 방지: v2 (#2).

### 아직 브라우저에서 확인하지 않은 것
- 홈 레이아웃 편집기의 드래그 동작, 실시간 재접속 표시, 기록 화면, 순위 화면과 위젯, 카드 라우팅, 리팩터링 후 예매 지도 회귀.
